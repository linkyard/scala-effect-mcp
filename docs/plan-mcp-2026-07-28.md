# Plan: MCP 2026-07-28 with legacy compatibility

Target: public interface conforms to MCP `2026-07-28` only. The implementation additionally serves legacy clients (`2025-06-18`, `2025-11-25`) on stdio and Streamable HTTP. Existing user code is not kept compatible. Release as `0.4.0` (early-semver, breaking).

Spec source: `modelcontextprotocol/modelcontextprotocol`, `docs/specification/2026-07-28`, `schema/2026-07-28/schema.ts`.

## 1. Target architecture

```
user code ──► McpServer[F] (stateless, 2026-07-28 types only)
                 ▲
          ServerCore (dispatch, _meta validation, capability checks,
                      input-required, caching hints, subscriptions, errors)
             ▲                        ▲
   ModernFrontend               LegacyFrontend (package `legacy`)
   (per request)                (initialize state machine, ping, setLevel,
                                 resources/subscribe, input-required resolver,
                                 downgrade codec)
             ▲                        ▲
        jsonrpc2 (request-scoped output streams)
             ▲                        ▲
   stdio (era chosen by message)   http4s (POST modern; legacy sessions opt-in)
```

Legacy code lives in `legacy` packages of the existing modules and is enabled through configuration. No separate artifacts: legacy support needs no extra dependencies.

## 2. Public API (mcp-server)

### 2.1 Server

```scala
trait McpServer[F[_]]:
  def serverInfo: Implementation
  def instructions: F[Option[String]]

trait ToolProvider[F[_]] extends McpServer[F]:
  def tools(ctx: ListContext[F]): F[List[ToolFunction[F]]]          // may vary by authorization only
  def toolsCache: CacheHint = CacheHint.default
trait ToolChanges[F[_]] extends ToolProvider[F]:
  def toolChanges(ctx: ListContext[F]): fs2.Stream[F, Unit]

trait PromptProvider[F[_]] ...        // same shape: prompts, promptChanges
trait ResourceProvider[F[_]] ...      // resources(cursor), templates(cursor), read(uri, ctx): F[Outcome[ReadResult]]
trait ResourceChanges[F[_]] ...       // resourceListChanges
trait ResourceSubscriptions[F[_]] ... // resourceUpdates(uri, ctx): Stream[F, ResourceUpdated]
```

Removed: `McpServer.initialize`, `Session`, `Client[F]`, `ConnectionInfo[F]`, `RootChangeAwareProvider`, `ping`, unsolicited `elicit`, and the features deprecated in 2026-07-28: Logging, Sampling, Roots (no `log`, `sample`, `listRoots`, no `logging` capability). Client capability fields for them are decoded and ignored.

### 2.2 Request context

```scala
trait RequestContext[F[_]]:
  def client: ClientInfo                       // Option[Implementation], ClientCapabilities
  def authentication: Authentication
  def transport: JsonRpcConnection.Info
  def meta: Meta                               // user-visible _meta (trace context etc.)
  def input: InputContext                      // inputResponses + verified requestState of this retry
  def reportProgress(progress: Double, total: Option[Double] = None, message: Option[String] = None): F[Unit]
```

No protocol version on the context. Logging is not part of the API; applications log with their own logger (stderr or OpenTelemetry, as the spec recommends).

### 2.3 Results and input-required

```scala
enum Outcome[+A]:
  case Complete(value: A)
  case InputRequired(requests: Map[InputKey, InputRequest], state: Option[RequestState])

enum InputRequest:
  case ElicitForm(message: String, schema: ElicitSchema)
  case ElicitUrl(message: String, url: Uri)
```

Elicitation is the only input request type.
`tools/call`, `prompts/get`, `resources/read` return `F[Outcome[...]]`; all other handlers return plain results. The core rejects `InputRequired` containing a request the client did not declare (`MissingRequiredClientCapability`, -32021).

### 2.4 Interactive helper (replay)

```scala
ToolFunction.interactive[F, A, B](info, (args: A, ctx: RequestContext[F], ask: Ask[F]) => F[B])
// ask.elicit(key, message, fields*): F[ElicitResult]
// ask.all(...) batches several requests into one round
```

Each round re-runs the function from the start. Earlier answers are replayed from `requestState`; the first unanswered `ask` short-circuits with `InputRequired`. Side effects before the last `ask` repeat per round; documented as the contract.

### 2.5 Request state

`RequestStateCodec[F]`: HMAC-SHA256 (javax.crypto, no new dependency), payload = principal id, expiry, method, name/uri, SHA-256 of arguments, user state bytes. Rejects tampered, expired, cross-principal and cross-request state. Required server config: key (+ rotation list), TTL, `principal: Authentication => F[Option[String]]`.

### 2.6 Caching

`CacheHint(ttl: FiniteDuration, scope: CacheScope)`; default `ttl = 0`, `scope = Private`. Applied to `server/discover`, `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`, `resources/read`. Never on input-required results or on retries carrying `inputResponses`/`requestState`.

### 2.7 Errors

Semantic errors in the API: `McpError.ResourceNotFound(uri)`, `InvalidParams(msg)`, `NotFound(kind, name)`, `Internal`. Codes are assigned by the codec per era (resource not found: `-32602` modern, `-32002` legacy).

### 2.8 Tool definition

Add `icons`, free-form JSON Schema 2020-12 for `inputSchema`/`outputSchema`, `structuredContent: Json` (any value), `x-mcp-header` support. Validate `x-mcp-header` annotations when tools are listed (fail fast, spec constraints in streamable-http.mdx §Custom Headers). `tools/list` order deterministic (by name).

## 4. Order and milestones

1. **M1 protocol**: 1, 2.
2. **M2 modern core**: 3, 4, 5, 7. Modern stdio server usable.
3. **M3 modern HTTP + helper**: 8, 6, 13. Feature-complete for 2026-07-28.
4. **M4 legacy**: 9, 10, 11, 12.
5. **M5 release**: 14, 15, publish `0.4.0`.

M3 is releasable on its own as a modern-only milestone (`0.4.0-M1`) if legacy work slips.

## 5. Risks

- **Ecosystem lag**: few clients speak 2026-07-28 yet; the Inspector and Tier-1 SDKs have betas. Legacy path carries real traffic first, so M4 should not be cut.
- **Replay semantics** of `interactive` surprise users with repeated side effects. Mitigation: documentation, plus `Outcome`-based API stays available for full control.
- **requestState key management**: rotation and multi-instance deployments need the same key; missing config must fail at startup, not at first input request.
- **Strict legacy clients** rejecting unknown fields: the downgrade codec strips, so golden tests for legacy output are needed (no official examples exist for 2025-11-25; hand-written fixtures from the 2025-06-18/2025-11-25 `schema.json`).
- **Tasks extension** (`io.modelcontextprotocol/tasks`) out of scope; capability not advertised.

## 6. Open decisions (defaults chosen)

| Decision | Default |
|---|---|
| Legacy versions | 2025-06-18 and 2025-11-25; 2025-03-26 only via HTTP header fallback |
| HTTP response mode | JSON unless notifications possible |
| Legacy input loop | re-invoke handler (same semantics as modern), not fiber suspension; elicitation only |
| Default cache hint | `ttl 0`, `private` |
| Deprecated features (logging, sampling, roots) | not in the API; legacy `setLevel` and `roots/list_changed` are accepted and ignored |
| Legacy in separate artifact | no, opt-in config |
